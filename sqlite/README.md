# 할 일 (Todo)

내 컴퓨터에서만 도는 Todo 앱. 데이터는 `todo.db` 파일 하나에 저장되고 앱을 껐다 켜도 남는다.

## 실행

```
cd todo_list
npm install
npm start
```

브라우저에서 http://localhost:3000 을 연다. 터미널 하나, 포트 하나로 끝난다.

첫 실행 때 `todo.db` 가 없으면 저절로 만들어진다. 별도 초기화 명령은 없다.

## 기능

기본: 할 일 추가 / 목록 보기 / 완료 표시 / 삭제
추가: 마감일 / 태그 / 오늘 할 일만 보기 / 검색

- 마감일이 지난 미완료 항목은 빨간 배지로 표시된다.
- 태그는 입력창에 쉼표로 치면 없는 태그는 만들어지고 있는 태그는 재사용된다.
- 완료한 항목은 목록 맨 아래로 내려간다.
- 삭제는 확인을 한 번 묻고, 되돌릴 수 없다.

## 터미널에서 쓰기

브라우저를 열지 않고 같은 `todo.db` 를 다루는 `todo` 명령이 있다. 서버는 켜 두지 않아도 된다.
웹 화면과 같은 파일을 보므로 터미널에서 완료로 표시하면 브라우저에도 그대로 나온다.

```
npm run todo -- list
```

`todo` 한 단어로 쓰려면 이 폴더에서 한 번만:

```
npm link
```

그러면 어느 폴더에서든:

```
todo add 우유 사기 --due 2026-09-10 --tag 장보기,급함
todo list                # 미완료만. --all / --done / --today 로 바꾼다
todo list 우유 --tag 급함  # 제목·메모 검색과 태그 필터
todo done 3 5            # 여러 개를 한 번에. --undo 로 되돌린다
todo summary             # 오늘 끝낸 일. --date 2026-09-07 로 다른 날
```

`summary` 는 끝낸 시각을 앞에 붙이고 끝낸 순서대로 보여준다.

```
2026-09-08 요약
끝낸 일 2건 · 남은 일 10건 (이 날 마감 1건, 지난 마감 4건)

09:12  #3    [x]  2026-09-08  책 반납  #공부
14:40  #9    [x]  2026-09-08  장바구니 결제하기  #장보기 #집안일
                              쌀 10kg 하고 세제 같이
```

제목은 따옴표 없이 여러 낱말로 써도 되지만, **옵션 값이 여러 낱말이면 따옴표로 묶어야
한다**. `--notes 저지방으로 두 개` 라고 쓰면 `--notes` 는 `저지방으로` 만 먹고 남은 낱말이
제목 뒤에 붙는다. 그래서 옵션 뒤에 낱말이 남으면 저장하지 않고 이유를 보여준다.

`src/cli.js` 는 `db.js` 의 함수만 부른다. SQL 은 `server.js` 와 마찬가지로 여기에도 없다.

걸리는 지점들:

- PowerShell 은 `--tag 장보기,급함` 의 쉼표를 배열 구분자로 읽고 공백으로 이어 붙여 넘긴다.
  Bash 는 그대로 넘긴다. 두 셸에서 같게 동작하도록 `cli.js` 가 쉼표와 공백을 모두 구분자로
  받는다. 대신 터미널로는 공백이 든 태그 이름을 만들 수 없다 — 그런 이름은 화면에서 만든다.
- `done_at` 은 UTC 다. `date(done_at, 'localtime')` 로 옮겨야 한국 시간 오전 9시 전에 끝낸
  일이 어제 요약에 잡히지 않는다. "오늘" 을 로컬 시각으로 계산하는 것은 화면과 같다.
- `todo` 명령에는 `--env-file-if-exists` 플래그를 붙일 자리가 없다. 그래서 `cli.js` 가
  `process.loadEnvFile()` 로 `.env` 를 직접 읽는다. 이걸 빼면 `DB_PATH` 를 바꿔 둔 사람은
  웹 앱과 터미널이 서로 다른 `todo.db` 를 보게 된다.

## 구성

```
todo_list/
├── package.json
├── .env.example       # .env 로 복사해서 쓴다
├── .env               # 커밋하지 않는다
├── schema.sql         # 표 3개 정의. 서버가 뜰 때마다 실행된다(IF NOT EXISTS)
├── todo.db            # 데이터. 커밋하지 않는다
├── src/
│   ├── server.js      # Express 앱과 API. SQL 은 여기 없다
│   ├── cli.js         # 터미널용 todo 명령. 여기도 SQL 은 없다
│   ├── db.js          # DB 열기와 모든 SQL
│   ├── db-check.js    # npm run db:check
│   └── api-check.js   # npm run api:check
└── public/
    ├── index.html
    ├── app.js
    └── style.css
```

의존성은 `express` 하나다. SQLite 는 Node 24 에 내장된 `node:sqlite` 를 쓰므로
따로 설치하거나 컴파일할 것이 없다. 빌드 단계도 없다.

## 데이터 구조

표 3개다.

- `todos` — 할 일 하나가 한 행. 제목, 메모, 완료 여부, 마감일, 완료 시각(`done_at`)
- `tags` — 태그 이름의 원본. 이름을 바꿀 때 한 행만 고치면 된다
- `todo_tags` — 둘을 잇는 연결표. 할 일 하나에 태그 여러 개, 태그 하나에 할 일 여러 개

SQLite 를 쓸 때 걸리는 지점들:

- 외래키는 연결마다 직접 켜야 한다(`PRAGMA foreign_keys = ON`). 안 켜면 `ON DELETE CASCADE`
  가 동작하지 않고 `todo_tags` 에 고아 행이 화면 증상 없이 쌓인다.
- `schema.sql` 은 전부 `IF NOT EXISTS` 다. 그래서 **이미 있는 표에는 새 열을 못 붙인다.**
  `done_at` 을 나중에 넣으면서 `db.js` 가 `PRAGMA table_info` 로 열이 있는지 보고 없으면
  `ALTER TABLE ADD COLUMN` 을 한 번 실행한다. 이게 없으면 새로 만든 DB 만 동작하고 쓰던
  `todo.db` 는 `no such column: done_at` 으로 죽는다.
- 완료 시각은 `is_done` 과 짝이라 `updateTodo` 에서 같이 바꾼다. 이미 완료인 항목에 다시
  `done: true` 가 와도 처음 끝낸 시각을 지키려고 `CASE WHEN is_done = 1 THEN done_at ...`
  으로 거른다. `UPDATE` 의 `SET` 오른쪽 식은 **바뀌기 전 행의 값**을 본다는 점을 이용한다.
- `DATE` 타입이 없다. 마감일은 `TEXT` 에 `YYYY-MM-DD` 로만 넣는다. 그래야 사전순 정렬이
  날짜순과 일치한다. `schema.sql` 의 `GLOB` 검사가 다른 형식을 입구에서 막는다.
- `date('now')` 는 UTC 다. 한국 시간 오전 9시 전에는 어제 날짜가 나온다. "오늘" 은
  브라우저에서 로컬 시각으로 계산해 서버로 넘긴다.
- `ORDER BY due_date` 는 NULL 을 먼저 정렬한다. 마감일 없는 항목을 뒤로 보내려면
  `ORDER BY due_date IS NULL, due_date` 로 써야 한다.

## 확인하는 방법

### DB 가 설계대로 만들어졌는가

```
npm run db:check
```

표 3개(`todos`, `tags`, `todo_tags`), 인덱스 2개, 외래키 `1` 이 나오고 `=> 전체 통과` 로 끝나야 한다.

### API 가 동작하는가

서버를 켠 상태에서 다른 터미널에서:

```
npm run api:check
```

검사 20개가 전부 PASS 여야 한다. 만든 항목은 끝에서 스스로 지우므로 기존 데이터는 그대로다.

`curl` 로 직접 확인하지 않는 이유: Windows 의 Git Bash 에서 `curl -d` 에 한글을 넘기면
인수가 CP949 로 변환되어 서버에는 깨진 바이트가 도착한다(저장된 값이 `U+FFFD` 가 된다).
앱 문제가 아니라 curl 인수 인코딩 문제지만, 확인 수단으로는 쓸 수 없다.

### 화면에서 손으로 확인할 것

| 확인할 것 | 어떻게 |
|---|---|
| 추가 | 제목을 넣고 추가 → 목록에 나타난다 |
| 완료 표시가 저장됨 | 체크 → F5 → 체크 상태가 유지되고 맨 아래로 내려가 있다 |
| 삭제 | 삭제 → 확인 → 사라진다. F5 해도 안 돌아온다 |
| 껐다 켜도 남음 | 서버를 Ctrl+C 로 끄고 `npm start` → 목록이 그대로다 |
| 마감일 | 어제 마감 항목만 빨간 "지남" 배지가 붙는다 |
| 오늘 | "오늘" 필터 → 내일 마감 항목이 사라진다 |
| 태그 | 태그 칩을 누르면 목록이 줄고, 같은 태그가 중복 생성되지 않는다 |
| 검색 | `%` 한 글자만 쳤을 때 전체가 나오지 **않는다** |
| 빈 제목 | 제목을 비우고 추가 → 이유가 화면에 보이고 추가되지 않는다 |

## 지금 없는 것

로그인, 휴지통/되돌리기, 반복 일정, 우선순위, 하위 할 일, 배포. 전부 의도적으로 뺐다.

완료 시각은 나중에 넣었다(`done_at`). 그 전에 이미 완료였던 행은 시각을 알 수 없어서
`updated_at` 으로 한 번 어림잡아 채웠다 — **그 행의 시각만 추정이고 이후 완료분은 정확하다.**
채워 넣는 `UPDATE` 가 `trg_todos_updated_at` 를 깨우므로 그 행들의 `updated_at` 은
마이그레이션 시각으로 바뀐다.
